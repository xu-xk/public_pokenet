# 客户端查询：重复请求与过期回复

## 问题

玩家反复打开和关闭进度面板时，旧实现会清理在途状态并再次发起请求。连续操作可能产生重复查询，随后到达的响应也可能因请求身份变化被丢弃。

## 设计

- 将查询状态绑定连接、会话代际和角色，防止切换角色后使用旧响应。
- 同一身份只保留一个逻辑在途请求；面板隐藏不等于取消已发送请求。
- 成功结果短暂缓存；失败进入冷却，超时后可以再次尝试。
- 相关游戏事件发生时标记缓存失效；请求在途时不并发发第二个请求。

```text
打开面板 → 校验角色与会话 → 复用在途 / 使用缓存 / 发起请求
                                  ↓
                  响应身份有效 → 更新状态 → 展示
                  超时或失败 → 冷却 → 允许重试
```

## 验证与边界

3 个受影响生产源码文件及定向测试重新编译，11 项 JUnit 通过，覆盖连续开关、超时、迟到响应、角色切换和缓存失效。旧逻辑在重复点击的对照用例中产生第二次请求，修复后通过；玩家实际测试反馈该问题已解决。
